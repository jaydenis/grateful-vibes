# Technical Specification: Grateful Vibes

## 1. System Overview & Architecture

* **High-Level Purpose:** Grateful Vibes is a listening app for Grateful Dead live
  concerts. It loads the Internet Archive's stream-only `GratefulDead` collection,
  collapses each concert date to one recording, and streams the resulting catalog
  through a custom in-page audio player. A song index from Relisten adds an
  artist-wide "every performance of this song" browse mode. The app is packaged with
  Tauri 2 as a desktop and mobile application, with an optional desktop-only path
  that routes playback to Sonos rooms over the local network.
* **Architecture Style:** Static, client-rendered single-page application written in
  vanilla JavaScript ES modules, with no backend, no database, and no API keys. The
  UI is event-driven: a central mutable `state` object is projected into the DOM by
  explicit render functions, and a small player module emits typed events to its
  subscribers. The native side is a thin Tauri shell plus seven IPC commands that
  proxy SSDP discovery and UPnP/SOAP control to Sonos hardware. There is no native
  audio service; audio always plays in the platform webview's `<audio>` element
  unless the user switches output to Sonos.
* **Primary Tech Stack:**
  * **Frontend language/runtime:** JavaScript (ES modules, `"type": "module"`),
    browser DOM and Web Audio-adjacent HTMLMediaElement APIs, `localStorage`,
    Media Session API, `ResizeObserver`, `matchMedia`.
  * **Build:** Vite `^8.3.4` (`vite.config.js`), with `__APP_VERSION__` injected at
    build time from `package.json`.
  * **Styling:** Custom CSS (`src/style.css`) plus Bootstrap `^5.3.8` CSS only. No
    Bootstrap JavaScript is imported.
  * **Native shell:** Tauri `2.12.4` (Rust crate), `@tauri-apps/api ^2.12.4`,
    `@tauri-apps/plugin-opener ^2.7.2`, Tauri CLI `^2.12.3`.
  * **Rust:** edition 2024, `rust-version = "1.98"`, `serde`/`serde_json`, `log`,
    `tauri-plugin-log`, `tauri-plugin-opener`, `reqwest 0.12` (blocking +
    rustls-tls), and the exactly pinned `sonos-api =0.9.0` and
    `sonos-sdk-discovery =0.9.0` (imported as `sonos_discovery`).
  * **Data sources:** Archive.org's `advancedsearch.php`, `metadata/{identifier}`,
    and `download/{identifier}/{file}`; Relisten's keyless `api/v2` songbook and
    `api/v3` song history. Both are public, CORS-enabled, and unauthenticated.
  * **Persistence:** browser `localStorage` under the `grateful-vibes:` namespace.
  * **Testing/linting:** none configured (see Section 6).

## 3. Data Models & State Management

### 3.1 Database Schema / Entities

**Not Implemented / None Found.** There is no database, ORM, migration, or server-side
storage. All data is either fetched per session or persisted as JSON in
`localStorage`.

#### In-memory entities

**Show** (produced by `normalizeShow` in `src/api.js`, stored in `state.shows`):

| Field | Type | Source / rule |
| --- | --- | --- |
| `id` | `string` | Archive `identifier`; records without one are dropped |
| `date` | `string \| null` | First `YYYY-MM-DD` match in Archive's `date`; else `null` |
| `title` | `string` | Archive `title` with a leading "The Grateful Dead Live at" and trailing "on YYYY-MM-DD" stripped; falls back to venue, then "Untitled recording" |
| `venue` | `string` | Archive `venue`, trimmed |
| `coverage` | `string` | Archive `coverage`, trimmed free text |
| `views` | `number` | Archive `downloads` (all-time views), default 0 |
| `source` | `string` | Derived from `identifier`: `SBD`, `AUD`, `MTX`, `FM`, or `''` |
| `detailsUrl` | `string` | `https://archive.org/details/{encodeURIComponent(id)}` |

**Group** (venue/year/history pickers, built by `buildGroups` /
`buildHistoryGroup` in `src/main.js`):
`{ key, label, shows: Show[], labels: Map<string, number> }`, where `key` is the
normalized label or `__unknown__`, and `labels` counts raw spellings to choose the
most common display label. A group's displayed count is `group.shows.length`.

**City tree nodes** (built by `buildCityTree`):
`country: { key, label, labels, shows, regions: Map, cities: Map, hasRegions }`,
`region: { key, label, labels, shows, cities: Map }`,
`city: { key, label, labels, shows }`. `hasRegions` is true when at least one show in
that country resolved a state/province; if false, cities hang directly off the
country and the region level is skipped. The temporary `entries` array is deleted
after construction.

**Track** (produced by `fetchShowTracks` in `src/api.js`):

| Field | Type | Rule |
| --- | --- | --- |
| `id` | `string` | `` `${identifier}:${file.name}` `` |
| `url` | `string` | `https://archive.org/download/{id}/{encoded path segments}` |
| `title` | `string` | Archive file `title`, else the filename humanized |
| `duration` | `number \| null` | `length` parsed from `HH:MM:SS`/`MM:SS` or float seconds |
| `number` | `number` | 1-based position after sorting |
| `unavailable` | `boolean` (optional) | Added at runtime by `player.js` after a media error |

**Songbook entry** (produced by `fetchSongbook`):
`{ key, label, count, countLabel: 'shows', slugs: string[] }`. Entries are collapsed
case-insensitively by display name; `key` and `count` come from the most-played slug
variant, and `slugs` lists every variant with `shows_played_at > 0`.

**Song history result** (`fetchSongShows`):
`{ name: string, shows: [{ date: 'YYYY-MM-DD', venue: string, location: string }] }`.

#### Persisted entities (`src/storage.js`, version 1)

* Keys: `grateful-vibes:v1:settings`, `grateful-vibes:v1:session`,
  `grateful-vibes:v1:recent`.
* `settings`: `{ version: 1, volume?: number (0–1), theme?: string }`. Reads default
  volume to `0.85`; a missing theme resolves to the default palette later.
* `session`: `{ version: 1, showId, showTitle, showDate, trackId, trackIndex,
  trackTitle, time, updatedAt }`. Requires `showId` and `trackId` strings, a
  non-negative finite `time`, and a numeric `updatedAt` no older than 30 days.
  Invalid, stale, or version-mismatched sessions are treated as absent.
* `recent`: array of `{ id, title, date, playedAt }`, newest first, capped at 6
  entries by `addRecentShow`. Invalid entries are filtered on read.
* All reads and writes are wrapped in `try/catch`; unavailable or corrupted storage
  degrades to defaults. `clearAllData()` removes the three known keys and then any
  remaining key starting with `grateful-vibes:`, so older prefixes are also purged.

### 3.2 State Lifecycles

**Central UI state.** `src/main.js` owns one `state` object:

```text
shows[], total, recordings, visible (page size 40), loading,
query (normalized, >= 3 chars), searchRaw,
trackQuery, trackSearchRaw,
dimension ('venue'|'year'|'history'|'city'|'song'|null), value (group key),
city { country, region, city },
song { list, loading, loaded, error, selectedKey, selectedName, selectedSlugs,
       shows, totalShows, showsLoading, showsError },
selectedId, show, tracks, tracksLoading
```

A parallel `output` object holds audio-routing state:
`{ mode: 'local'|'sonos', supported, rooms[], roomId, roomIds[], selectionLocked,
sonos: { queue, index, context, playing, sawPlaying, currentTime, duration, volume },
polling }`.

**Render pipeline.** `render()` is a thin wrapper: it calls `renderView()` and then
`syncUrl()`. `renderView()` decides between the root choice grid, a picker
(venue/year/city/song), and a show list, and rewrites the relevant DOM regions
(choice cards, drill bar, status line, picker list, show list, load-more). Filtering
never mutates the source arrays; `visible` implements `Load more` in increments of 40.

**URL synchronization.** Browse state is mirrored with `history.replaceState` (never
`pushState`, so the back button remains navigation) into these query parameters:
`browse`, `group`, `country`, `region`, `city`, `song`, `q`. `restoreFromUrl()` runs
once, after the catalog loads; it refuses to overwrite the incoming URL before it has
read it (`urlRestored`). A linked song waits for the lazy songbook, then selects the
song via `pendingSongKey`.

**Catalog lifecycle.** On boot: load settings → apply theme and volume → build theme
menu → `loadCatalog()`. `fetchCatalog()` requests up to 20 pages of 10,000 rows,
concatenates them, dedupes by date (keeping the highest `views`), and sorts newest
first. `loadCatalog()` then builds venue/year groups, builds the city tree, renders,
applies any URL view, and finally attempts `restoreSession()`. Errors populate the
inline `#list-alert` with a retry action (`listRetryAction`, which can point at the
catalog, the songbook, or a song history).

**Song lifecycle.** The songbook is fetched lazily the first time the Song dimension
is opened and cached in `state.song.list`. Selecting a song aborts any in-flight
history request with a shared `AbortController`, fetches every variant slug (results
cached in module-level `songShowsCache` for the session), merges performances by
date, and intersects them with the catalog's date map. Shows therefore only appear
when the stream-only vault has a recording for that night; the status line reports
the Relisten total versus the available count.

**Playback lifecycle.** `createPlayer()` owns exactly one active `<audio>` and, when
needed, one spare. Track state lives in the player; `main.js` renders it through
`player.on(...)` events (`track`, `time`, `preload`, `playpause`, `volume`, `error`)
and `snapshot()`. The session is saved at most every 4 seconds on time updates and
immediately on play/pause, `pagehide`, visibility change, and native back/exit. On
restore, `player.restore(show, tracks, index, time)` loads the track paused at the
saved position; playback only starts when the user presses play.

**Sonos lifecycle.** `initializeSonos()` runs only under Tauri. It calls
`sonos_supported`, reveals the output selector, discovers rooms, and starts a
1-second `pollSonos` interval. Choosing Sonos stops local playback and starts the
current track on the selected room; choosing one room plays directly, choosing two
joins the second to the first's RINCON id. Room selection locks while a show is
playing and is released by Stop or by the end of the queue. When a track that had
started and was playing reports `STOPPED` at (or within about a second of) its known
duration, the poller advances to the next queue item and calls `sonos_play` again.

## 4. Interface & API Specifications

### 4.1 External HTTP Endpoints

| Purpose | Method & URL | Query / response handling |
| --- | --- | --- |
| Catalog search | `GET https://archive.org/advancedsearch.php` | Query `q=collection:(GratefulDead AND stream_only)`, `rows=10000`, `page=1..20`, `output=json`, `fl[]` for `identifier,date,title,venue,coverage,downloads`, `sort[]=date desc`. Reads `response.docs` and `response.numFound`. Non-2xx throws `Archive.org search failed (HTTP {status}).` |
| Show files | `GET https://archive.org/metadata/{identifier}` | Reads `files[]`; `is_dark` throws "no longer available"; no playable files throws. |
| Audio stream | `GET https://archive.org/download/{identifier}/{file}` | Used as the `<audio>` `src` and by Sonos. 302-redirects to a range-capable storage node. |
| Songbook | `GET https://api.relisten.net/api/v2/artists/grateful-dead/songs` | Expects an array of `{ slug, name, shows_played_at }`; non-array throws. |
| Song history | `GET https://api.relisten.net/api/v3/artists/grateful-dead/songs/{slug}` | Reads `name` and `shows[]` with `display_date`/`date`, `venue.name`, `venue.location`. |

All frontend fetches accept `{ signal }` from an `AbortController` and pass it to
`fetch`. Track selection prefers every file of format `VBR MP3`; if none, `MP3`; if
none, `Ogg Vorbis`. Private files (`private === 'true'`) are excluded. Files are
sorted by filename with numeric collation, then by a track number parsed from
`file.track` or a `t\d+` token in the filename.

### 4.2 Internal Module Contracts

**`src/api.js`**

```js
COLLECTION_QUERY: string
dedupeShows(shows: Show[]): Show[]
fetchCatalog({ signal }?): Promise<{ shows: Show[], total: number, recordings: number }>
fetchSongbook({ signal }?): Promise<SongEntry[]>
fetchSongShows(slug: string, { signal }?): Promise<{ name: string, shows: Performance[] }>
fetchShowTracks(identifier: string, { signal }?): Promise<{ identifier: string, tracks: Track[] }>
```

`fetchCatalog` exits early when a page returns fewer than `MAX_ROWS` items or when
`collected.length >= numFound`. The dedupe key is `show.date`, falling back to
`item:{id}` for undated recordings.

**`src/player.js`**

```js
createPlayer(): {
  on(listener: (type, snapshot) => void): () => void,
  playShow(context, tracks, startIndex = 0, shouldPlay = true): void,
  restore(context, tracks, startIndex = 0, seconds = 0): void,
  toggle(): void,
  next(): void,
  prev(): void,
  seek(seconds: number): void,
  setVolume(value: 0..1): void,
  stop(): void,
  snapshot(): Snapshot,
}
```

`Snapshot` = `{ queue, index, track, context, playing, currentTime, duration,
volume, hasNext, hasPrev, preload, crossfading, error }`. `volume` is the user's
level, never a fade gain. `preload` is `{ index, ready }` or `null`.

Constants: `PRELOAD_WINDOW = 30` seconds, `CROSSFADE_SECONDS = 2`,
`FADE_TICK_MS = 40`. On a media error the active track is marked `unavailable`, an
`error` event is emitted, and playback advances to the next non-unavailable track up
to five consecutive failures. `prev()` restarts the current track when more than 3
seconds have elapsed or it is the first track.

**`src/storage.js`**

```js
loadSettings(): { volume: number, theme: string|null }
saveSettings({ volume?, theme }?): void
loadSession(): Session|null
saveSession(session): void            // stamps updatedAt, ignores missing showId/trackId
clearSession(): void
loadRecentShows(): RecentEntry[]
addRecentShow(show): RecentEntry[]    // dedupes, unshifts, caps at 6
clearRecentShows(): void
clearAllData(): void
```

**`src/themes.js`**

```js
THEMES: { id, name, colors: [string, string, string, string, string] }[]  // 26 palettes
DEFAULT_THEME_ID = 'shakedown-street'
normalizeThemeId(id): string          // legacy slug -> current id
getTheme(id): Theme                   // unknown id -> default
themeActionColor(colors): string      // mix colors[0] 24% toward #04201c
themeBackground(colors): string       // mix colors[0] 7% toward #080a12
chooseAccentText(colors): '#ffffff' | '#06201a'
readableInk(color): string            // AA-lifted ink for small text
themeInks(colors): string[]
```

Palette order is primary, secondary, highlight, support, surface tint. `readableInk`
tests contrast against `#111521`, `#151a28`, and both panels tinted 20% with the
candidate color, targeting 4.5:1; it lifts HSL lightness in 0.01 steps up to 1.0 and
returns the first passing color.

### 4.3 Tauri IPC Commands

Registered in `tauri::generate_handler!` in `src-tauri/src/lib.rs`. The frontend calls
these only behind `isTauri()`. JavaScript argument names are camelCase and map to the
Rust snake_case parameters. Every command except `sonos_supported` returns
`Result<T, String>`; a rejection surfaces as a JS promise rejection whose reason is
the error string.

| Command | JS arguments | Returns |
| --- | --- | --- |
| `sonos_supported` | — | `boolean` (`true` on Windows, macOS, Linux; `false` on mobile) |
| `sonos_discover` | — | `{ id, name, rinconId }[]`, sorted case-insensitively by name |
| `sonos_play` | `{ playerId, url, title }` | `null`; rejects on non-HTTPS URL, unreachable/non-audio stream, or transport failure |
| `sonos_control` | `{ playerId, action, value? }` | `null`; `action` is `play`, `pause`, `stop`, `seek`, or `volume`; `value` is stringified seconds or 0–100 volume |
| `sonos_status` | `{ playerId }` | `{ state, transportStatus, position, duration }` |
| `sonos_player_join` | `{ playerId, coordinatorRinconId }` | `null`; joins a room to a coordinator |
| `sonos_player_leave` | `{ playerId }` | `null`; makes the room a standalone coordinator |

On mobile, all Sonos commands reject with
`"Sonos local output is available in desktop builds only."` except
`sonos_supported`, which resolves `false`.

**Rust-side behavior (`src-tauri/src/sonos.rs`):**

* Discovery uses `sonos_discovery::get_with_timeout(Duration::from_millis(2600))`,
  dedupes by IP address, rejects RINCON ids that are not `RINCON_` plus ASCII
  alphanumerics/underscore, and prefers the room name over the device name.
* Playback validates an HTTPS URI, performs a `Range: bytes=0-0` preflight with a
  blocking `reqwest` client (8-second timeout, max 10 redirects, user agent
  `GratefulVibes/1.0 Sonos controller`), and requires an audio content type (or
  `octet-stream`, `.mp3`, `.ogg`). It builds a DIDL-Lite metadata document with
  escaped values, then issues `SetAVTransportURI` followed by `Play`.
* `control` implements Play, Pause, Stop, Seek (`REL_TIME`, formatted
  `HH:MM:SS`), and RenderingControl `SetVolume` (`Master`, 0–100).
* `join` sends `x-rincon:{coordinator}` as the transport URI; `leave` calls
  `BecomeCoordinatorOfStandaloneGroup`.
* `status` combines `GetTransportInfo` and `GetPositionInfo` and parses
  `HH:MM:SS` into seconds.
* Error mapping rewrites UPnP `401`/`606` failures into a message pointing at Sonos
  Connection Security / UPnP settings.

### 4.5 CSS Token Interface

`applyTheme()` in `src/main.js` sets on `document.documentElement`:

* `--theme-1` … `--theme-5` — raw palette colors (fills, borders, gradients).
* `--theme-1-ink` … `--theme-5-ink` — contrast-lifted variants for text/icons.
* `--theme-action` — darker solid accent color. It is written at runtime but no
  rule in `src/style.css` currently consumes it.
* `--accent-text` — `#ffffff` or `#06201a`, chosen for contrast on `--theme-1`.
* `data-theme` — the active theme id.
* `meta[name="theme-color"]` — the computed page background.

`src/style.css` consumes these through `--gd-*`, `--ink-*`, `--bg`, `--bg-soft`,
`--surface`, `--line`, `--line-strong`, `--text`, `--muted`, `--radius`,
`--header-h`, and `--np-h`. Colors are combined with `color-mix(in srgb, ...)`; no
JavaScript or stylesheet should hardcode a new palette color.

## 5. Implementation Boundaries & Guardrails

### Always Do

* **Use vanilla JavaScript and DOM APIs.** No framework, state library, templating
  language, or Bootstrap JavaScript. Bootstrap is CSS only; header menus and dialogs
  are hand-rolled with focus management.
* **Keep every network request abortable.** New API functions take `{ signal }` and
  pass it to `fetch`; UI code aborts superseded catalog/panel/song requests.
* **Use the theme contract.** Consume `--theme-N` for fills/borders/gradients and
  `--ink-*` for small text and icons. Route new palette colors through
  `readableInk()`; never hardcode palette hex values in CSS.
* **Mirror new browse state in both `syncUrl()` and `restoreFromUrl()`**, or shared
  links silently drop it.
* **Version persisted shapes.** `storage.js` namespaces keys with
  `grateful-vibes:v1:`; changing a stored shape requires bumping `VERSION` and
  migrating, and `clearAllData()` must keep clearing any `grateful-vibes:` key.
* **Keep the two CSPs in sync.** `app.security.csp` and `app.security.devCsp` in
  `src-tauri/tauri.conf.json` must both allow any new host — `connect-src` for APIs,
  `media-src` for audio.
* **Register Tauri commands twice.** Add every `#[tauri::command]` to
  `generate_handler!` in `src-tauri/src/lib.rs`, and add any permission beyond
  `core:default` to `src-tauri/capabilities/default.json`.
* **Keep exactly one active audio element.** Playback state is read through
  `player.snapshot()`; never cache an element reference across a track change, and
  never treat a crossfade gain as the user's volume.
* **Preserve the versioning chain.** `package.json` is the source of truth;
  `tauri.conf.json` reads `"version": "../package.json"`; the frontend gets
  `__APP_VERSION__` from `vite.config.js`.
* **Match local conventions.** 2-space indent, single quotes, semicolons, CRLF
  source files, comments that explain *why*. Update `README.md` when behavior
  changes; theme additions must also appear in the README's theme list.
* **Keep native Rust changes minimal and formatted.** `src/lib.rs` and
  `src/sonos.rs` are `cargo fmt --check` clean; `build.rs` and `src/main.rs` retain
  the upstream template's 2-space indentation.

### Never Do

* **Do not add downloads, accounts, favorites, user playlists, non-Grateful-Dead
  content, a web backend, or API keys.** Static and keyless is deliberate.
* **Do not add a JavaScript framework, state manager, linter, formatter, or test
  runner** unless explicitly requested; none is configured today.
* **Do not use `data-bs-*` toggles, modals, or dropdowns.** The Bootstrap JS bundle
  is never loaded.
* **Do not bump `sonos-api` or `sonos-sdk-discovery`** beyond the exact `=0.9.0`
  pins without hardware to verify against.
* **Do not run `npm run dev`, `npm run build`, or `npm test` merely to check
  compilation.** All three start with `npm version patch|minor --no-git-tag-version`
  and dirty `package.json`/`package-lock.json`; use `npx vite build` for a
  side-effect-free frontend check.
* **Do not reformat `build.rs` or `src/main.rs`** as a drive-by change.
* **Do not let a new API host ship without a CSP entry.** Both CSP strings allow
  `'self'`, `ipc:`, `http://ipc.localhost`, `archive.org`, `*.archive.org`, and
  `https://api.relisten.net` under `connect-src`. Add new API hosts to both, and
  new audio hosts to both `media-src` directives.
* **Do not reset or rewrite user data outside `clearAllData()`.** The reset flow is
  the only sanctioned destructive operation.

### Explicit Non-Features

No authentication, no user accounts, no server-side rendering, no service worker or
offline cache, no internationalization layer, no analytics, no error-reporting
service, and no automated CI/test pipeline exist in this repository.

## 6. Development, Testing & Verification

### Environment Setup & Commands

```bash
npm install                 # frontend dependencies
npm run dev                 # bump patch version, then Vite on http://localhost:5173 (strict port)
npm run build               # bump minor version, then vite build into dist/
npm test                    # bump patch version, then vite build (no test suite)
npm run preview             # serve dist/
npx vite build              # side-effect-free compile check; writes only ignored dist/
```

Desktop/mobile scripts:

```bash
npm run desktop:dev         # tauri dev, native window with Vite hot reload
npm run desktop:build       # tauri build for the host OS
npm run tauri dev|build     # aliases
npm run android:init|dev|build
npm run ios:init|dev|build  # macOS + Xcode only; the CLI omits ios on Windows
```

Prerequisites: Node and npm; Rust 1.98+ with edition 2024 and the platform Tauri
prerequisites for native builds; Android SDK, NDK, and JDK 17+ for Android; Xcode on
macOS for iOS. Android builds on Windows also need Developer Mode or
`SeCreateSymbolicLinkPrivilege` for the Tauri CLI's symlinks. Generated mobile
projects live under `src-tauri/gen/`; Windows installers are written under
`src-tauri/target/release/bundle/`.

Serving `dist/` requires HTTP (do not open `index.html` from disk). Archive and
Relisten both send permissive CORS headers, so any static host works for the web
build.

### Testing Frameworks

**Not Implemented / None Found.**

* No test files, test runner, assertion library, or coverage tooling exist.
* `npm test` is not a test command; it bumps the patch version and runs
  `vite build`.
* No linter or formatter is configured for JavaScript or CSS.
* There is no CI configuration (no `.github/` workflows).
* Rust has no test modules; verification is compile- and lint-based.

### Verification Procedure

**Frontend:**

```bash
npx vite build                              # exit 0; confirms the production bundle builds
```

Then run `npm run dev` (accepting its version bump) or serve `dist/` with
`npm run preview`, and exercise the affected flow in a browser: load the catalog,
open each browse dimension, open a show, play/pause/seek/skip, filter with 3+
characters, reload with a shared URL, reload to restore the saved session, switch a
theme, and use Reset data.

**Rust / Tauri:**

```bash
cd src-tauri
cargo check
cargo clippy
cargo fmt --all --check
```

`cargo fmt --all --check` is expected to report diffs in `build.rs` and
`src/main.rs` only (upstream template indentation). `src/lib.rs` and `src/sonos.rs`
must stay clean. Sonos changes require a real desktop host with reachable speakers
and UPnP enabled; there is no mocked hardware harness.

**Packaged builds:** verify that both `csp` and `devCsp` permit every host the
changed flow contacts, and that the command is present in `generate_handler!` plus
`capabilities/default.json` when it needs permissions beyond `core:default`.
